# Инструменты переезда на новую версию

Написаны при переносе форка с 2.1.247 на 2.1.260, обкатаны на 2.1.260 → 2.1.269
2.1.269 → 2.1.273, 2.1.273 → 2.1.276, 2.1.276 → 2.1.278, 2.1.278 → 2.1.280 и
2.1.280 → 2.1.284.
Без них следующий переезд начнётся с того, что их придётся писать заново.

## Что чем занято

| Файл | Зачем |
|---|---|
| `build.py` | пакует `ext/` в `dist/claude-code.vsix`, `--install` — и ставит |
| `syntax.mjs` | разбор обоих бандлов acorn'ом: ловит синтаксис, и только его |
| `verify.py` | сверка наших функций ПО ФОРМЕ: тело сводится к скелету, где короткие имена заменены номером появления, и скелеты сравниваются. Совпадение текста ничего не значит — имена перемангливаются каждой сборкой |
| `scope.mjs` | имена в нашем коде, уходящие мимо объемлющих функций в модульную область. Третья проверка, и единственная, поймавшая две подмены: `x1`→`M1` (ссылка на поле ввода) и `E$`→`_$` (алиас `vscode`) |
| `freevars.mjs` | вендорные зависимости и сироты внутри тел `function fork*` |
| `port.py` | переносчик: поиск по форме, имена позиционно, карта модульных имён |
| `namemap.py` | сама карта и снимается ей: тот же поиск по форме, но по ОБЪЯВЛЕНИЮ имени. Раньше карта набивалась глазами — 24 имени за раз это не работа для глаз |
| `rebase.py` | ханк, не легший `port.py`, переносится правка-за-правкой: прежний вендорский участок выравнивается с новым difflib по форме, каждая правка ставится к своему соседу. `--применить` пишет, без него — только отчёт |
| `placement.py` | пятая проверка — РАССТАНОВКА: правки «вендор → форк» прежней версии и «вендор → порт» новой сравниваются по форме вместе с вендорной строкой перед каждой. Ловит код, вставленный не туда, который разбирается и совпадает по форме |
| `enclosure.py` | шестая проверка — В ЧЬЁМ ТЕЛЕ стоит правка: для каждой нашей строки берётся первый строковый литерал её верхнеуровневого объявления, и последовательности форка и порта сравниваются. Ловит правку, переехавшую в чужую функцию с таким же хвостом, — её пропускает `placement.py`, который смотрит на одну соседнюю строку |
| `check-install.py` | готовность к установке: что стоит, что зарегистрировано, что осталось мусором |
| `where.py` | где в новой версии начинается окно ханка: контекст сводится к скелету и ищется по форме. Вход для `rebase.py`, которому нужна строка цели. `--строк N` расширяет контекст, когда форма неоднозначна |
| `g.py` | дешёвый построчный поиск по огромным бандлам: `g.py <файл> <регэксп> [сколько]` |
| `show.py` | показать тело функции по имени |

## Чего здесь нет намеренно

`audit.py` — поиск опасных мест слиянием эвристик. Отчитался «подозрительных 0»,
когда настоящих было шесть. `scan-api.py` — проверка на съехавший API поиском
имён, которых больше нет в бандле: не поймала бы `utilization` (имя в бандле
осталось, пропало только поле сессии), а все семь её находок были ложными.

## Пути внутри

`port.py` и `verify.py` больше НЕ держат путей: прежняя версия задаётся им
файлами в аргументах. Так вышло не из любви к чистоте — зашитый
`/home/kaltsit/Ledevia/Projects/claude-code-vsc` пережил переезд форка в
`claude-trah` молча, и инструменты искали бы дерево, которого нет. `graft.py` и
`regraft.py` держали путь до конца и с 2.1.269 не понадобились ни разу; удалены
02.10.2026.

Прежняя версия задаётся ДВУМЯ файлами — чистым вендором и нашим форком, — а не
коммитом гита: история форка при переезде схлопнута в один коммит.

## Порядок переезда

Ниже — как это прошло на 2.1.269, по шагам и с числами.

1. Достать вендорный vsix новой версии **и предыдущей** (маркетплейс отдаёт
   старые версии: `_apis/public/gallery/publishers/anthropic/vsextensions/claude-code/<версия>/vspackage?targetPlatform=linux-x64`),
   распаковать, прогнать оба через один и тот же prettier.
2. Снять опись наших правок: `diff` чистого вендора прежней версии с нашим
   форком. На 2.1.269 вышло 6 ханков в `extension.js` и 36 в вебвью.
   **Часть ханков — шум форматирования**: prettier не идемпотентен по переносам
   внутри объектов, и развёрнутый вход даёт другую разбивку, чем
   минифицированный. `port.py` их отличает и пропускает; не принимать за правку.
3. `namemap.py` — карта модульных имён. Кого спрашивать, говорит `scope.mjs`,
   запущенный по НАШЕМУ файлу прежней версии: он печатает ровно те имена, на
   которые наш код опирается снаружи.
4. `port.py` дважды, с разными картами (`--карта вебвью` / `--карта расширение`).
   На 2.1.269 легло 6 из 6 и 26 из 34; восемь оставшихся — места, где вендор
   изменился не только именами, и они делаются руками.
5. `syntax.mjs`, `verify.py`, `scope.mjs`, `freevars.mjs` — четыре разные
   проверки, и ни одна не заменяет другую. Решающая из них — `scope.mjs` по
   ПЕРЕНЕСЁННОМУ файлу: в его выводе не должно остаться ни одного имени от
   прежней версии. Осталось — значит имя не переехало, и это падение вебвью.
6. Собрать, поставить, **прогнать живьём**. Разбор, сверка по форме и поиск
   сирот были зелёными ровно в тот раз, когда вебвью падало при первой отрисовке.
7. В репозиторий — двумя коммитами: чистый вендорный дроп, затем наши патчи.

## Слепое пятно, уронившее вебвью 12.09.2026

`scope.mjs` искал наши области среди операторов и объявлений функций. Поле
класса — `PropertyDefinition`, оператором оно не является, и строки вида
`forkFocus = e1(null);` в проверку не попадали ВООБЩЕ. Имя `e1` (фабрика
сигнала в 2.1.260; в 2.1.269 она зовётся `t1`) уехало в новую версию как есть.

Все четыре проверки были зелёными. Вебвью при этом рисовал только оболочку
вкладки: заголовок и кнопки на месте, тела разговора и поля ввода нет. Ровно
тот отказ, про который предупреждает пункт 6 порядка переезда.

Почему позиционный вывод не спас: рядом с этими полями не оказалось ни одной
вендорской строки с тем же вызовом. Соседнее `forkNewSessionRequested = new w9()`
переехало правильно именно потому, что двумя строками выше стоит вендорское
`permissionRequested = new w9()`, и пара `w9` → `z9` вывелась из неё.

Починено с двух сторон: `scope.mjs` теперь считает своими и поля, и методы
класса с именем `fork*`, а `e1` внесено в карту `port.py` явно.

## Склейка разнесённых правок — переезд 2.1.273, 16.09.2026

`port.py` видит ханк как «контекст до, удалённое, добавленное, контекст после».
Если внутри одного ханка форка две правки разделены вендорными строками,
удалённое склеивается в один блок, которого в файле нет. Итог двоякий.

- **Не легло, и это честно:** 6 из 36 ханков вебвью. Разложены `rebase.py` без
  единого промаха.
- **Легло не туда, и это опасно:** ветка `else if` хода подагента встала ВНУТРЬ
  `if` вместо места после его скобки. Отчёт `port.py` сказал «перенесён». Поймал
  разбор, но только потому, что вышел синтаксический мусор. Второй такой случай
  разбирался чисто: строка `forkCwd` уехала в `watch()`. Поймала его только
  `placement.py`.

Отсюда порядок: после `port.py` и `rebase.py` — `placement.py`. Расхождений
должно остаться ровно столько, сколько объяснено словами. На 2.1.273 их три:
вендор убрал две строки `h();`, после которых стояли наши блоки. `createSession`
вынес подписки в `watch($)`, и `forkCwd` переставлен в `createSession` руками.
Подписка `onForkNewSessionRequested` уехала в `watch` правильно и теперь
работает и для восстановленных сессий.

## Полосы в чужом теле — переезд 2.1.280, 22.09.2026

После установки из вкладки пропали полоса расхода с окнами лимита и полоса
агентов с фоновыми задачами. Все пять проверок были зелёными.

`port.py` поставил `F(forkHud, …)` и `F(forkAgentBar, …)` не в конец композера,
а в заголовок инструмента NotebookEdit. Хвост там тот же — `}), }), ],` — и
позиционный поиск нашёл его раньше. `placement.py` сверяет правку с одной
соседней вендорской строкой, а она `}),` в обоих местах. Строки встали в код,
который рисуется только при правке ноутбука, и вкладка просто перестала их
показывать — без ошибки.

Отсюда `enclosure.py`: он сравнивает не соседа, а объявление, в теле которого
стоит правка, по его первому строковому литералу. На сломанной сборке он
показал `стало 248622: NotebookEdit`, на исправленной — только объяснённое
расхождение (отпавший ханк 27). Порядок проверок теперь: разбор, форма,
область, сироты, расстановка, тело.

## Мёртвая правка: имя ссылки слилось с модульным — переезд 2.1.280, 22.09.2026

Починка потери фокуса при смене раскладки звала `B1.current`. В форке 2.1.278
`B1` — это модульный jsx-помощник `Fragment`, а не ссылка на поле ввода:
`B1.current` там `undefined`, и правка молча не делала ничего. Настоящая ссылка
в композере зовётся `editableRef` и в 2.1.278 называлась `f1`.

Как это вышло: короткое имя ссылки совпало по форме с модульным именем, и
карта перенесла его как модульное — ровно то встречное переименование, про
которое предупреждает раздел ниже. Ни одна из пяти проверок этого не видит:
разбор чист, форма совпадает, `scope.mjs` считает `B1` законным модульным
именем, сирот нет, расстановка на месте. Ловится только чтением или живым
прогоном — «фокус не возвращается» выглядит как каприз VS Code.

Починено при переезде на 2.1.280: правка переписана на настоящую ссылку
(`l1` в 2.1.280), а все её локальные имена стали длинными и с приставкой
`fork`, чтобы слиться им было не с чем.

## Переезд 2.1.284, 29.09.2026: мёртвая правка поймана до установки

- **Вендор 2.1.280 маркетплейс больше не отдаёт.** Базой служит чистый дроп из
  гита: `git archive <коммит дропа> claude-code-vsc/ext/...`.
- **Ссылка поля ввода сменилась ещё раз:** `l1` → `y1`. После `port.py` имя `l1`
  осталось в правке фокуса и в 2.1.284 разрешалось в модульную функцию. На этот
  раз его поймал `scope.mjs`: в выводе по перенесённому файлу было имя прежней
  версии. Правило: весь вывод `scope.mjs` сверяется с картой, и лишнее имя —
  не шум, а падение или мёртвая правка.
- **Ветка хода подагента в пятый раз встала внутрь `if`.** Разбор поймал её,
  переставлена за закрывающую скобку.
- **Вендорская функция сменила сигнатуру:** `YI1($, J, Z)` → `Mk1($, J, Z, X)`.
  Её вызов стоит в нашем ханке 34 контекстом и перенесён вендорской формой.
- **Ханк 7** (`forkBackgroundTasks`, `forkStopTask`) потерял вендорский
  контекст и вставлен перед `async setModel($)` руками. Поля `connection` и
  `claudeChannelId` у класса на месте.
- Итог проверок: разбор обоих бандлов; `verify.py` 53/53; `scope.mjs` без имён
  2.1.280; сирота только `isFinite`; `placement.py` 50/50 и 6/6; `enclosure.py`
  одно объяснённое расхождение: вендор добавил литерал `"string"` в тот же класс
  выше строки `forkConversation`, и отпечаток сменился.

## Ловушка, стоившая отдельной правки

В 2.1.269 модульный помощник jsx зовётся `F`. В нашем коде 2.1.260 локальная
переменная тоже звалась `F` — и, перенесённая дословно, она затёрла бы
модульную внутри своей функции. Это ровно то слияние имён, которое ищет
`verify.py`, только возникшее не при переносе, а от встречного переименования.
Лечится тем, что наши локальные имена пишутся длинными и осмысленными:
минификация уже позади, экономить на них нечего.
