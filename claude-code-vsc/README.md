# claude-code-vsc — форк расширения Claude Code для VS Code

Официальное расширение `anthropic.claude-code` распаковано сюда и прогнано через
prettier. Текущая версия — **2.1.287**.

Обновление идёт **двумя коммитами**: сначала чистый вендорный дроп (распаковка
нового vsix, ни одной нашей правки), следом наши патчи поверх него. Слияние тремя
сторонами тут невозможно: между 2.1.247 и 2.1.260 сменились 194 938 строк из
264 429, между 2.1.260 и 2.1.269 — 152 854 в вебвью и 160 580 в `extension.js`, между 2.1.269 и
2.1.273 — 152 313 и 134 991, между 2.1.273 и 2.1.276 — 165 558 и 189 530, между 2.1.276 и 2.1.278 — 100 615 и 131 456, между 2.1.278 и 2.1.280 — 130 925 и 177 059, между 2.1.280 и 2.1.284 — 60 806 и
107 908, между 2.1.284 и 2.1.287 — 78 291 и 105 885 добавленных строк
(`git diff --numstat` от чистого дропа прежней версии).
Совпадение по тексту при этом ничего не значит: короткие имена перемангливаются
каждой сборкой. Функции переносятся целиком и сверяются ПО ФОРМЕ, скелетами с
пронумерованными именами.

Личность пакета остаётся `anthropic.claude-code` — форк ставится **поверх**
официального расширения и заменяет его.

## Что он добавляет к официальному

Правок 42: шесть в `extension.js` и тридцать шесть в вебвью. По сути это:

- **полоса расхода** — сколько потрачено, видно прямо в панели, с разбивкой;
- **отдельные ленты подагентов** — работа каждого подагента идёт своей строкой,
  а не сливается в общий поток; в ленту агента можно войти кнопкой на блоке его
  вызова, и после того, как он закончил, тоже;
- **задачи включены и уводятся в фон.** Апстрим гасит их строкой
  `CLAUDE_CODE_ENABLE_TASKS = "0"` — потому что вебвью нечем было их показать.
  Здесь есть и список фоновых, и кнопка «в фон», поэтому переменная не
  трогается, а в самом CLI задачи включены по умолчанию;
- **рабочий каталог сессии** виден в шапке и в списке, и его можно выбрать:
  рядом заведётся новая сессия в выбранном каталоге, а начатая останется
  нетронутой (`forkPickDirectory` — заглушка в базовом классе, диалог у хоста
  VS Code, случай в разборе управляющих запросов);
- **выжимка размышления просится всегда.** `thinkingSummariesDefaultOn` у
  апстрима отвечает «нет», и в запуск не уходит `--thinking-display`; блок
  размышления при этом приезжает пустым. Здесь он отвечает «да», а явная
  настройка `showThinkingSummaries` по-прежнему сильнее;
- **блок инструмента переписан**: знак рода действия перед именем (читали,
  правили, искали, ходили в сеть), длительность и число строк вывода,
  раскрытие по умолчанию для правок и ошибок, разбор ключей MCP-инструментов
  вместо общего перебора, отдельный разбор вывода Serena;
- **вырезаны плашки-анонсы** — «Prefer the Terminal experience?» и подобные;
- **починена потеря фокуса** в поле ввода при смене раскладки.

Всё остальное — официальное расширение как есть.

Апстрим в 2.1.269 подошёл вплотную к одной из этих правок: у него появились
карта агентов, строки прогресса подагентов в Focus view и `stopSubagent` через
`query.stopTask`. Наш `fork_stop_task` делает то же самое своим маршрутом, и
пока оставлен как есть: вебвью зовёт его, а переписывать вебвью ради апстримного
имени дороже, чем оставить. Пересмотреть, когда апстрим начнёт показывать
фоновые задачи сам.

## Установка

Нужно: **VS Code**, **python3** и команда `code` в PATH. Node и npm не нужны —
сборка это упаковка каталога в zip.

**1. Забрать репозиторий.**

```bash
git clone <адрес этого репозитория> ~/claude-code-vsc
cd ~/claude-code-vsc
```

**2. Понять про нативный бинарь.** Начиная с 2.1.260 расширение таскает с собой
собственную сборку CLI — один файл на 205 МБ. В гит он не положен намеренно
(история росла бы на столько же при каждом обновлении), поэтому после клонирования
его в дереве нет. Отсюда два пути, и первый проще:

- **путь А, обычный.** Бинарь не нужен вовсе: в настройках указывается ваш
  собственный `claude`, и расширение запускает его. Ничего скачивать не надо,
  переходите к шагу 3;
- **путь Б, если хотите пакет «как у всех».** Скачайте официальный `.vsix` с
  Marketplace, распакуйте его как zip и положите файл
  `extension/resources/native-binary/claude` в
  `ext/extension/resources/native-binary/`. Сборка его упакует.

**3. Собрать и поставить.**

```bash
python3 tools/build.py --install
```

Скрипт пакует `ext/` в `dist/claude-code.vsix` и зовёт
`code --install-extension … --force`. Форк встаёт **поверх** официального
расширения: идентификатор у них один.

**4. Указать, чем запускать CLI.** Это обязательный шаг для пути А и не лишний
для пути Б. В настройках VS Code (`Ctrl+Shift+P` → `Preferences: Open User
Settings (JSON)`):

```json
"claudeCode.claudeProcessWrapper": "/полный/путь/к/claude"
```

Путь пишется полный, без `~`: расширение подставляет строку как есть. Годится
и обычный `claude` из PATH (`which claude` покажет путь), и любая своя сборка
или скрипт-обёртка.

Почему без этого не заработает путь А: расширение ищет исполняемый файл в
таком порядке — настройка, потом бинарь внутри пакета, потом ошибка
«Unsupported platform». Отката на системный `claude` из PATH у него **нет**.

**5. Перезапустить окно.** `Ctrl+Shift+P` → `Developer: Reload Window`.

**6. Проверить, что встало именно это.**

```bash
python3 tools/check-install.py
```

Печатает только выводы: какая версия установлена, откуда (`source: vsix`),
закреплена ли она, какие строки про `claude` лежат в настройках и на месте ли
нативный бинарь.

### Что надо знать заранее

- **Автообновление форк не трогает.** Сайдлоад пишет в `extensions.json` метку
  `"source": "vsix"` и `"pinned": true`. Обратная сторона: новые версии
  официального расширения тоже сами не приедут — обновлять надо руками.
- **Подпись не проверяется.** В пакете её нет вообще, маркетплейс подписывает
  при отдаче.
- **Вернуться к официальному** — удалить расширение в VS Code и поставить
  `anthropic.claude-code` из Marketplace заново.

## Что откуда взято

Сборки `win32-x64` и `linux-x64` содержат **побайтно одинаковые**
`extension.js`, `webview/index.js`, `webview/index.css` и `package.json`.
Различаются только нативные довески. Значит код платформонезависим, и в
репозитории он лежит без единого бинаря.

Не положено в репозиторий намеренно:

- `resources/native-binary/claude` — 205 МБ собственной сборки CLI. С 2.1.260
  расширение таскает его с собой; в гит он не кладётся, иначе история росла бы
  на столько же при каждом дропе. Берётся из вендорного vsix, сборка его
  упакует;
- `resources/audio-capture/x64-*/audio-capture.node` — захват звука, оставлен
  только под текущую платформу.

## Как расширение находит CLI

`resolveClaudeBinary()` (`ext/extension/extension.js:163485`):

```
claudeProcessWrapper задан  -> исполняемый = он, бинарь пакета уходит в аргументы
не задан, бинарь есть       -> исполняемый = бинарь пакета
не задан, бинаря нет        -> ошибка «Unsupported platform»
```

Отката на системный `claude` в PATH **нет**. Поэтому в настройках обязательно:

```json
"claudeCode.claudeProcessWrapper": "/путь/к/патченому/claude"
```

Бинаря в пакете нет, поэтому `executableArgs` останется пустым и запустится
ровно указанный файл.

Побочный эффект настройки: `resolvePermissionModeInCli` становится `false`
(`extension.js:163372`) — режим разрешений считает не CLI, а расширение.

## Что расширение делает с окружением сессии

`ext/extension/extension.js:164819` на каждый запуск:

```js
X.MCP_CONNECTION_NONBLOCKING = "true";
X.CLAUDE_CODE_ENTRYPOINT = "claude-vscode";
delete X.CLAUDECODE;
delete X.CLAUDE_CODE_CHILD_SESSION;
delete X.TRACEPARENT;
delete X.TRACESTATE;
```

Строка `CLAUDE_CODE_ENABLE_TASKS = "0"` нами **убрана**. Апстрим гасил задачи
потому, что вебвью нечем было их показать: ни списка фоновых, ни Ctrl+B. Теперь
есть и то и другое — строки агентов под полосой расхода и кнопка «в фон». В
самом CLI задачи включены по умолчанию, гасит их только явное «false», поэтому
переменную просто не трогаем.

Пользовательские `claudeCode.environmentVariables` подмешиваются **до**
`CLAUDE_CODE_ENTRYPOINT`, то есть его через настройку не переопределить.

## Сборка

```
tools/build.py            # dist/claude-code.vsix
tools/build.py --install  # и поставить
```

Подпись не проверяется: в пакете её нет вообще, маркетплейс подписывает при
отдаче. Сайдлоад пишет в `extensions.json` метку `"source": "vsix"` и
`"pinned": true` — такое расширение VS Code автообновлением не трогает.

## Устройство вебвью

`webview/index.js` минифицирован, но **не обфусцирован**: дерево JSX цело,
имена свойств настоящие, все видимые строки на месте. Мангались только
локальные имена. Таблица CSS-классов служит таблицей символов:

```js
var e4 = { container: "container_7xV4vA", usageTrack: "usageTrack_7xV4vA", … };
```

Любой компонент находится за один поиск по строке его класса.

CSP вебвью — `script-src 'nonce-…'`: свой код должен жить внутри `index.js`,
рядом положить скрипт нельзя.

Протокол вебвью↔хост снимается из журнала даром — расширение само пишет в свой
канал вывода `Received message from webview: <JSON>`.
