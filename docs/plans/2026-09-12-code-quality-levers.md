## ГЛАВНОЕ: указания про качество кода отрезает lean-промпт

Системный промпт собирает `ow(e,n,r)`. Первым делом она спрашивает `d=Ij(s)`, а
`Ij` — это `leanPrompt(модель)`. Дальше всё классическое семейство секций
заменяется одной:

```js
...d ? [ORo(P,n)]
     : [vRo(P), xRo(n), P===null||P.keepCodingInstructions===!0 ? CRo() : null,
        ARo(), RRo(O), MRo()]
```

`CRo()` — это и есть раздел `# Doing tasks` с пятью прямыми указаниями о коде.
**В ветке `d` он не вызывается никогда**, а Opus 5 идёт именно по ней.

Пять пунктов, которые из-за этого не приезжают (дословно из `CRo`):

1. «Don't add features, refactor, or introduce abstractions beyond what the task
   requires. A bug fix doesn't need surrounding cleanup; a one-shot operation
   doesn't need a helper. Don't design for hypothetical future requirements.
   **Three similar lines is better than a premature abstraction.** No
   half-finished implementations either.»
2. «Don't add error handling, fallbacks, or validation for scenarios that can't
   happen. Trust internal code and framework guarantees. Only validate at system
   boundaries (user input, external APIs). Don't use feature flags or
   backwards-compatibility shims when you can just change the code.»
3. «Default to writing no comments. Only add one when the WHY is non-obvious: a
   hidden constraint, a subtle invariant, a workaround for a specific bug,
   behavior that would surprise a reader. If removing the comment wouldn't
   confuse a future reader, don't write it.»
4. «Don't explain WHAT the code does, since well-named identifiers already do
   that. Don't reference the current task, fix, or callers ("used by X", "added
   for the Y flow", "handles the case from issue #123"), since those belong in
   the PR description and rot as the codebase evolves.»
5. «For UI or frontend changes, start the dev server and use the feature in a
   browser before reporting the task as complete.»

**Проверено** прямым чтением промпта живой сессии 12.09.2026: разделов
`# System` и `# Doing tasks` нет, вместо них `# Harness` — то есть `ORo`. Про
код в lean-промпте остаётся ОДНА фраза: «Write code that reads like the
surrounding code: match its comment density, naming, and idiom». Она приходит из
`if(Ij(e))return"…"`, и вторая фраза, про комментарии, лежит в соседней ветке и
до нас не доезжает:

> «Only write a code comment to state a constraint the code itself can't show,
> never to say where it came from, what the next line does, or why your change
> is correct; that's you talking to the reviewer, not the next reader, and it's
> noise the moment the change merges.»

### Что проверили и отмели

**Стиль вывода ни при чём.** `P.keepCodingInstructions` читается только в
НЕ-lean ветке. Флаг `keep-coding-instructions: true` в
`output-styles/serena-first.md` стоит с самого начала и работает — просто в
нашей ветке его никто не спрашивает. Винить стиль было бы ошибкой.

**`# Delivering work` на роль якоря не годится.** Раздел (`LRo`) приходит по
условию `a.CLAUDE_CODE_BISON_CAIRN ?? (ice(m)||Zyr(s))` — собственный вентиль. В
офлайн-пробе комплекта его нет вовсе: `trah.py verify` 12.09.2026 показал `НЕ
доставлено` сразу у трёх кусков (`sys-delivering-work-at-full-scope`,
`sys-delegation-calibrated` и первой редакции нового куска). Это НЕ регрессия
наших правок: штатный непатченый бинарник в той же пробе даёт то же самое.
Стенд `qbench` меряет `claude -p`, так что кусок, привязанный к `LRo`, до замера
не доехал бы вовсе. Первая редакция нового куска была привязана именно туда и
поэтому переписана.

**Якорь выбран внутри lean-ветки** — хвост строки
`…naming, and idiom.";`, где `.";` это закрывающая кавычка JS, а не текст
промпта (без неё та же фраза совпадает дважды). Минифицированных имён вроде `Ij`
в якоре нет намеренно: они меняются от сборки к сборке. Свойство якоря, ради
которого он и выбран: уйдём с lean-промпта — ветка не сработает, и пять пунктов
приедут сами из `CRo()`. Ни дыры, ни дублирования ни в одном из двух миров.

### Почему заметка комплекта оказалась ложной

В куске `sys-delivering-work-at-full-scope` стояло: «остальное семейство
doing-tasks править не понадобилось… совпадающее не трогаем». Заметка описывала

## Чужие замеры, на которые опирается этот кусок

Три агента-разведчика вернулись 12.09.2026. Здесь только то, что меняет решение
по ЭТОЙ задаче; остальное — в их отчётах, перечитывать незачем.

**За то, чтобы правило жило в промпте, а не в файле-своде.** ETH Zurich +
LogicStar, 300 задач SWE-bench Lite плюс 138 задач из реальных PR 12 репозиториев,
у каждого из которых уже был свой `AGENTS.md`: контекстные файлы **не дают
прироста** success rate и добавляют **больше 20% к стоимости**; файлы,
сгенерированные моделью, success rate **снижают** примерно на 3% относительно
полного отсутствия контекста (arXiv 2602.11988). Проблема не в непослушании —
инструкции из файлов агенты исполняют хорошо; лишние требования просто усложняют
задачу.

**За то, чтобы кусок был коротким.** Порог числа инструкций в контексте: при 10
правилах доля безупречных ответов 59–94%, при 20 — 35–83%, при 40 — 9–31%, при
80 и выше — 0–2%, «жёсткий пол, а не плавная асимптота». 5 моделей, 20 прогонов
на условие, 4800 оценённых испытаний (arXiv 2607.19257). Разметка markdown
против простого текста — шум (−4,8…+2,1 п.п.) при +22–37% токенов. Отсюда и
решение не добавлять свод в бриф, где кусков уже 38.

**Чего от куска ЖДАТЬ, а чего нет.** SlopCodeBench: 20 итеративных задач, 93
чекпойнта, 11 моделей, 990 выходов. Anti-slop и plan-first промпты подняли
стартовые метрики примерно на треть, вдвое срезали эрозию и на 33% — многословие,
**и при этом pass rate не вырос ни у одной модели** (arXiv 2603.24755). Для нас
это ровно то, что надо: механические привычки и так 20/20, правильность вывода
5/5, и двигать мы собираемся не их, а вкус. Ждать от куска роста корректности
было бы ошибкой.

**Оговорка против нашего же стенда.** LLM-судья по качеству кода обманывается
поверхностью: шесть типов подставы, пять языков, GPT-4o теряет до 26,7 п.п.
точности, средняя девиация по Go 7,7 п.п.; длина кода и обилие комментариев
надувают оценку без улучшения функциональности (arXiv 2505.16222, Findings EACL
2026). Промпт `qbench/judge.py` это частично гасит («Do not reward length,
comments, or robustness the siblings do not have»), но полностью снять не может.
Поэтому решает не абсолютная оценка, а РАЗНИЦА между двумя условиями на одном
судье.

**Осторожно с ограничениями в тексте задания.** 100 задач на 8 веб-фреймворках:
по мере накопления структурных требований В ТЕКСТЕ способные конфигурации теряют
в среднем 30 п.п. assertion pass rate (arXiv 2605.06445). То же ограничение,
проверяемое машиной, наоборот помогает. Наш кусок — про минимальность и идиому,
а не про структуру слоёв, но правило «архитектуру словами не задают» записано
здесь, чтобы не пробовать заново.

**Почему кусок не просит перечитать свой дифф.** Интроспективная самокоррекция
без внешнего сигнала не улучшает результат (arXiv 2310.01798, ICLR 2024). Разбор
2026 года показывает механизм: тот же самый ошибочный тезис, переклеенный из
рассуждения модели во ВНЕШНЮЮ роль (сообщение пользователя, ответ инструмента),
поднимает долю явных исправлений на 23–93 п.п., значимо в 10 конфигурациях из 12
(arXiv 2606.05976). Прежняя редакция `trah-code-minimality` просила именно
самопроверку и поэтому переписана на момент написания.

**Про тесты, которые агент пишет сам.** 500 issue SWE-bench Verified, 6 моделей:
Opus 4.5 пишет тесты в ~83% задач и решает 74,4%; GPT-5.2 пишет в 0,6% задач и
решает 71,8%. Уговорили GPT-5.2 писать тесты — доля выросла до 64,4%, чистый
прирост решённых НОЛЬ при +19,8% выходных токенов. McNemar `p > 0,05` везде
(arXiv 2602.07900). Правило «пиши тесты по ходу» в кусок не попало поэтому.

## Отброшено, с причиной

* **Хуки-заслоны на привычки** («не пиши в каталог, куда не заглянул», «поищи
  дубль имени»): замер показал 20/20 — ловили бы пустоту.
* **Кросс-модельное ревью чужой моделью.** arXiv 2607.21656: Codex, ревьюящий
  черновики Claude, роняет проходимость с 91,4% до 82,8% (p=.046), 3 починки
  против 13 регрессий. Обратное направление работает (71,6% → 89,7%). Совет
  `/ask-codex` из чужих гайдов для нашего случая вреден. `critical-reviewer` на
  `model: inherit` оставляем.
* **Гарды на `Stop`, сверяющие доклад с журналом улик** (claude-guard-hooks):
  репозиторий заархивирован автором в день публикации, 0 звёзд; плюс в
  сентябрьском чейнджлоге чинили потерю рассуждения при блокировке на `Stop`.
* **Память графом через ещё один MCP**: обмеренный потолок деградации 5–7
  серверов.
* **Стенд как программа исследований.** Владелец дважды сказал не тратить на это
  силы. Стенд остаётся инструментом проверки правок промпта, а не предметом.
