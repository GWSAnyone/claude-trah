# Хуки — что перехватывается и почему

Хук — это команда, которую Claude Code зовёт на событии и слушает её ответ. Наши
хуки существуют потому, что **инструкция в промпте не удерживает**: правило,
записанное текстом, соблюдается «в основном», а хук либо пропускает, либо нет.

Этот файл написан для того, кто настраивает машину или разбирается, почему
что-то запретили, — чтобы не читать девять скриптов подряд.

Проводка (какой хук на каком событии) лежит в `../settings-hooks.json` и
ставится `../bin/install-kit.py`.

## Что где стоит

| Хук | Событие | Что делает |
|---|---|---|
| `guard-destructive.py` | перед `Bash` | не пропускает команды, уничтожающие несохранённую работу: `git checkout -- <файл>`, `git reset`, `git clean`, `git stash`, `rm` по опасным путям. Отдельно ловит их внутри скриптов и ловушек — там они срабатывают сами, в неожиданный момент |
| `guard-serena-scope.py` | перед вызовами Serena | не пропускает поиск без области: без неё сканируется весь корень, ответ почти всегда шум, а ход потрачен |
| `nudge-serena.py` | перед `Bash` | ловит чтение и правку файлов проекта через оболочку (`cat`, `sed -i`, heredoc). Режимы: `warn` предупредить, `block` отказать, `off` молчать. Свои деревья берёт из `NUDGE_SERENA_ROOTS` |
| `serena-remind-shim.py` | перед любым вызовом | прокладка перед `serena-hooks remind`: не даёт апстриму считать грепом собственный `search_for_pattern` Serena и отказывать за «слишком много грепа» |
| `warn-grep-root.py` | перед `Bash` | предупреждает про `grep` от корня, который отфильтрован `.gitignore` и врёт нулём совпадений |
| `guard-session-launch.py` | перед `Bash` | требует поднимать сессии через `launch`: иначе новая сессия наследует окружение родительской и пропадает из реестра. **Ставится только если `launch` есть**, иначе запретил бы всё |
| `guard-tausik-write.py` | перед правками | роль надзирателя: пускает только markdown в `docs/`. Нужен тем, у кого есть Таусозавр |
| `checkpoint.py` | `PreCompact` / `PostCompact` / `UserPromptSubmit` | не даёт сжать контекст без записанного состояния, подшивает пересказ, возвращает указатель в контекст |
| `serena-session-start.py` | `SessionStart` | сообщает, какой проект активен в Serena, и подсказывает, что активировать |
| `restore-claude-wrapper.py` | `SessionStart` | возвращает на место обёртку `~/.local/bin/claude`, которую стирает обновление Claude Code — оно пересоздаёт точку входа симлинком, и делает это молча |

## Перестановка хука напоминания

На машине, где в `~/.claude/settings.json` ещё стоит апстримовый
`serena-hooks remind --client=claude-code`, вызовы `mcp__serena__search_for_pattern`
считаются грепом и на третьем подряд получают отказ. Перестановка — одним ходом:

    python3 workspace-setup/bin/swap-remind-hook.py --dry-run   # показать
    python3 workspace-setup/bin/swap-remind-hook.py             # переставить

Скрипт кладёт прокладку в `~/.claude/hooks/`, меняет в настройках ровно одну
строку и перед этим снимает свою копию `settings.json.bak-<отметка>`. Откат он
печатает сам, одной командой:

    cp ~/.claude/settings.json.bak-<отметка> ~/.claude/settings.json

Git в этом не участвует ни в какой роли — ни при перестановке, ни при откате.

## Как выключить

Хук — это строка в `~/.claude/settings.json`. Убрать строку — выключить хук.
У `nudge-serena.py` есть более мягкий путь: переменная `NUDGE_SERENA_MODE`
(`warn` / `block` / `off`), и уклад Таусозавра умеет ставить её на сессию —
так решение одного уклада не выключает дисциплину для всех.

## Где проходит граница «наше — чужое»

`nudge-serena.py` спрашивает про каждый путь, наше ли это рабочее дерево.
Раньше ответ давала метка `.serena/project.yml`, но метка отвечает на другой
вопрос, и обе ошибки были живыми: дерево без метки (`asynchronus`) хук не видел
вовсе, а клон в песочнице под `/tmp` с меткой внутри считал своим.

Теперь источников три, по убыванию силы:

1. **`NUDGE_SERENA_ROOTS`** — список корней через `:`, как в `PATH`. Умолчание
   `~/Ledevia`. Что внутри — наше всегда, метка не нужна. Список задаётся
   настройкой, а не тем, какой проект активирован в Serena: активен ровно один,
   а репозиториев у нас несколько;
2. **заведомо чужое** — системные каталоги, временные песочницы, чужие дома.
   Не наше никогда, даже с меткой внутри. Соседний НАШ репозиторий чужим не
   является: именно этой лазейкой символьный слой обходился целый день;
3. **метка `.serena/project.yml`** вверх по дереву — прежний способ. Он никуда
   не делся, он лишь перестал быть единственным, так что проект за пределами
   настроенных корней по-прежнему опознаётся.

Пустое значение (`NUDGE_SERENA_ROOTS=`) отключает первый источник: получатель
комплекта без `~/Ledevia` остаётся ровно на прежнем поведении.

## Правила, по которым они написаны

**Отказ должен объяснять себя.** Хук, который просто не пропустил, вынуждает
гадать; каждый наш отказ говорит, что именно не так и что делать вместо.

**Ложное срабатывание дороже пропуска — но не всегда.** Поэтому у дисциплины
инструментов три режима, а у гарда деструктивных команд — ни одного: там цена
пропуска необратима.

**У каждого хука есть тест рядом** (`*.test.py`). Хук ошибается молча: он
возвращает код и текст, которых человек обычно не видит, и сломанный хук
выглядит как отсутствующий. Запускать так:

```
python3 guard-destructive.test.py     # провалов: 0
```

Числом проверок не меряй — оно растёт. Критерий — «провалов: 0».
