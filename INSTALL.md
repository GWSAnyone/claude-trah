# Установка

Одна команда — `./trah`. Она же ставит с нуля, она же обновляет: шаги
идемпотентны, каждый сам смотрит, есть ли ему что делать. Отдельной команды
«установить» нет намеренно — она отличалась бы от «обновить» только тем, что
первый раз всё делается впервые.

Ставить будет агент — отдайте ему [SETUP-AGENT.md](SETUP-AGENT.md), там та же
последовательность в виде промпта. Как оно устроено внутри —
[MECHANICS.md](MECHANICS.md).

## Главное свойство этой установки

Поставленный наполовину комплект **не падает**. Он молча ведёт себя не так, как
задумано: хук, которого нет, не кричит — событие просто не срабатывает; кусок,
который не доехал, не жалуется — модель работает обычной.

Поэтому шаг «проверить» в конце не формальность. Это единственный способ
отличить «поставлено» от «похоже на поставленное».

## Что должно быть на машине заранее

| | зачем | обязательно |
|---|---|---|
| Linux + bash | обёртка — bash-скрипт | да (см. «Другие ОС») |
| `python3` (3.10+) | хуки, установщик и сама дверь | **да** |
| Claude Code, установленный штатно | оригинал в `~/.local/share/claude/versions/` | **да** |
| `uv` | им ставится Serena | для Serena |
| `node`, `npm` | патчер и MCP-серверы | для правок бинарника |
| `git` | клонировать патчер | для правок бинарника |
| `sha256sum`, `md5sum`, `stat -c` | сверки и кеш обёртки | GNU-форма, есть в Linux |

Проверять руками нечего: установщик печатает блок `ОКРУЖЕНИЕ` — что нашёл и чего
нет. Показать, ничего не записав:

```bash
./trah --check
```

## Три слоя, и что будет, если поставить не всё

| слой | что даёт | без чего не работает |
|---|---|---|
| хуки, агенты, навыки | гарды, разбор правок, чекпоинт, мерки | `python3` |
| бриф | дисциплина инструментов в кешируемой части промпта | обёртка `~/.local/bin/claude` |
| правки бинарника | то, что снаружи не настраивается ничем | `node`, `npm`, `git`, форк патчера |

`./trah` ставит все три. Пропустить третий можно, просто не заводя патчер: шаг
«сборка» отчитается провалом, комплект и обёртка встанут, а `claude trah` скажет
на stderr «патченой сборки нет — запускаю штатную» и поднимет обычную сессию —
с брифом и хуками, но без правок бинарника.

Первый слой ставится за минуту и ничего не патчит. Третий — самое ценное и самое
рискованное. Сомневаетесь — начните с первого.

## Шаг 1. Забрать репозиторий

```bash
git clone <адрес этого репозитория> ~/claude-trah
cd ~/claude-trah
```

Дальше все команды — из этого каталога. Где он лежит, комплект запоминает сам:
установщик пишет путь в `~/.claude/trah-kit-path`, и по этой памятке хук потом
находит образец обёртки. Каталог можно перенести, но тогда повторите `./trah` —
иначе памятка будет показывать в пустоту.

## Шаг 2. Serena и MCP-серверы

Половина комплекта построена вокруг символьного слоя: без Serena хуки дисциплины
будут напоминать об инструментах, которых нет.

```bash
uv tool install --from git+https://github.com/oraios/serena serena-agent
```

Одной установкой приезжают обе точки входа — `serena` и `serena-hooks`; на этой
машине обе легли симлинками в `~/.local/bin`. Если `serena-hooks` у вас не
оказалось, установщик не впишет блок `SessionEnd` и скажет об этом строкой в
докладе.

Серверы ставятся в пользовательскую область, одинаково для всех проектов:

```bash
claude mcp add serena -s user -- ~/.local/bin/serena start-mcp-server --context claude-code

claude mcp add sequential-thinking -s user -- npx -y @modelcontextprotocol/server-sequential-thinking

claude mcp add context7 -s user -- npx -y @upstash/context7-mcp --api-key ВАШ_КЛЮЧ

claude mcp add playwright -s user -- npx -y @playwright/mcp@latest \
  --headless --browser chromium --caps vision --output-dir ~/.claude/playwright-out
```

Про `context7`: ключ заводится на их сайте и **в репозиторий не кладётся
никогда**. Без ключа сервер не нужен — пропустите, остальное работает.

Про `playwright`: он тянет хромиум, ~656 МБ в `~/.cache/ms-playwright`. Без этого
сервера установщик не поставит навык `browser` — и правильно сделает: навык,
обещающий инструменты, которых в сессии не будет, уводит по ложному следу.

## Шаг 3. Патчер

Нужен только для третьего слоя. Форк, не апстрим: апстримный ломается на
модульном бандле Claude Code с версии 2.1.243.

```bash
git clone https://github.com/skrabe/tweakcc-fixed ~/.local/share/tweakcc-fixed
cd ~/.local/share/tweakcc-fixed
npx --yes pnpm@10 install --ignore-scripts
npx --yes pnpm@10 run build:dev
cd -
```

Через `npx`, а не `pnpm` напрямую: `pnpm` на машине может не стоять, а `npm`
лежит рядом с node всегда. Другой каталог патчера — переменной `TWEAKCC_DIR`.

### Предупреждение: скрипт правок исполняется без песочницы

Сборка зовёт патчер так:

```
node ~/.local/share/tweakcc-fixed/dist/index.mjs adhoc-patch \
  --script @/tmp/trah-build/edits.js  -p <копия бинарника> \
  --confirm-possible-dangerous-patch  --dangerous-no-script-sandbox
```

`--dangerous-no-script-sandbox` стоит не для удобства. Песочница tweakcc знает
флаги Node 20–24, а в Node 26 они снова переименованы, и с песочницей вызов не
проходит вовсе. Значит `edits.js` исполняется полноправным node-процессом: с
файловой системой и сетью, как любой ваш скрипт.

Скрипт свой — его собирает `собрать_скрипт()` из `trah-setup/fragments/*.md`, и
после сборки он остаётся на диске: `/tmp/trah-build/edits.js`. Прочитать его
прежде, чем доверять, — единственная разумная предосторожность здесь.

Сам патчер тоже собирается у вас из исходников, а не берётся готовым из npm.
Доверие к нему такое же, как к любому склонированному репозиторию, — не больше.

## Шаг 4. Одна команда

```bash
./trah --check     # ничего не пишет, показывает что изменилось бы
./trah             # поставить или обновить
```

В пустой дом ложится 52 файла — замер сегодняшний, `--dry-run --home /tmp/…`;
один навык пропускается, если нет MCP `playwright`.

Прицел — версия из `trah-setup/version.txt`, сейчас `2.1.263`. Если на машине
Claude Code новее, `./trah` сам поедет на неё: сверка якорей → сборка → проверка
доставки → все наборы проверок, и только последним шагом перепишет прицел.
Целиться в конкретную версию:

```bash
./trah --version 2.1.260
```

Разошедшиеся якоря — **штатное** явление, а не поломка комплекта: якоря
дословные куски минифицированного кода и живут ровно одну версию. `./trah`
называет их все разом; править в `trah-setup/fragments/*.md`.

### Что делает `./trah` — три шага, в этом порядке

**1. Комплект → `~/.claude`** (`trah-setup/bin/install-kit.py`).
Бриф, агенты, навыки, стиль вывода, все хуки (режим 0755), реестр модулей
диспетчера, кран строки состояния, контекст и память Serena в `~/.serena/`. И
памятка `~/.claude/trah-kit-path` — по ней потом находят этот каталог.

Чужого не трогает: в `settings.json` заменяется только `hooks`,
`permissions.deny` дописывается без дублей, `env`, `statusLine` и
`promptCacheTtl` — только если их там ещё нет. О своём значении, отличном от
нашего, установщик скажет и **не** перепишет. Отличающийся файл сохраняется
рядом как `<имя>.bak-<время>`. Если у вас своя проводка хуков, установщик её не
заменит и покажет, чем она отличается; согласны потерять свою —
`python3 trah-setup/bin/install-kit.py --replace-hooks`.

**2. Сборка → `~/.local/share/claude/trah/<версия>`** (`trah-setup/bin/trah.py`).
Патченая копия бинарника. Оригинал в `versions/` не трогается никогда: сумма
снимается до сборки и сверяется после. Ссылка `trah/current` показывает на
последнюю удачную сборку — на неё смотрит обёртка.

**3. Обёртка → `~/.local/bin/claude`** (`trah-setup/hooks/restore-claude-wrapper.py`).
Точка входа. Ставит её тот же код, что чинит её после каждого обновления Claude
Code, — второго установщика обёртки нет намеренно: две редакции одного действия
разъезжаются молча, а цена расхождения здесь — сессия без брифа, которая
выглядит совершенно обычной.

Если по этому пути лежал ваш собственный файл, он сохраняется рядом как
`claude.before-trah` — один раз, при первой замене. Симлинк штатного
установщика в сторону не копируется: он приезжает заново с каждым обновлением
Claude Code, а восстанавливается одной строкой `ln -s`.

Порядок не произволен. Комплект раньше сборки: сборка читает куски из комплекта.
Обёртка последней: она запускает то, что собрано двумя шагами выше, и поставить
её раньше значило бы на время оставить точку входа указывающей в пустоту.

**Зачем обёртке чиниться.** Штатный установщик Claude Code кладёт по пути
`~/.local/bin/claude` симлинк на новейшую версию и пересоздаёт его при каждом
обновлении, стирая обёртку. Хук на `SessionStart` возвращает её на место, а
образец берёт по памятке из шага 1.

## Шаг 5. Проверить

Не «должно работать», а фактом.

```bash
./trah status                                        # что где стоит
./trah tests                                         # ожидается: наборов 27, сорвалось 0
python3 ~/.claude/hooks/guard-destructive.test.py    # провалов: 0
claude --version                                     # обёртка не сломала обычный запуск
```

`./trah status` показывает прицел, новейшую версию на машине, есть ли патченая
копия, куда смотрит `current`, содержимое памятки и что лежит точкой входа —
обёртка, чужой файл или симлинк.

И живая проба: запустите `claude trah` и спросите сессию, видит ли она в своём
системном промпте строку про символьный слой. Если правки доехали — увидит.

## Шаг 6. Настройки, которые установщик не ставит

Часть вкусовые, часть выверена замером. Все живут в `~/.claude/settings.json`.

| ключ | значение | почему |
|---|---|---|
| `effortLevel` | `"medium"` | **выверено**: развёртка по двум задачам показала, что `xhigh` стоит +42 % времени и не даёт ничего |
| `autoCompactEnabled` | `false` | сжатие по заказу, а не по потолку окна |
| `enableWorkflows` | `false` | вместе с запретом `Workflow` в `permissions.deny` |
| `language` | `"Russian"` | комплект русскоязычный |

`hooks`, `env`, `permissions.deny`, `statusLine` и `promptCacheTtl` вписывает
установщик из `settings-hooks.json`.

**Про строку состояния.** `statusLine` указывает на кран `cache-tap.py`, а тот
зовёт дальше `claude-hud.sh` рядом с собой. Этого файла в комплекте нет — он из
плагина `claude-hud`. Не поставили плагин — кран молча выйдет, строка состояния
будет пустой, а счёт кеша всё равно будет копиться. Ничего не сломается.

**Про подагентов.** `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` (агент не зовёт
агента) и `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=6` вписываются установщиком.

## Шаг 7. Обезличить

В комплекте есть файлы, которые знают чужую машину и чужую экосистему. Они не
ломают работу, но будут давать неверные подсказки. Установщик перечисляет их сам
— блок «ОСТАЛОСЬ СДЕЛАТЬ РУКАМИ» в докладе.

| файл | что там | что делать |
|---|---|---|
| `hooks/nudge-serena.py` | `_ROOTS_DEFAULT = "~/Ledevia"` — где «наши» деревья | задать `NUDGE_SERENA_ROOTS` своим путём |
| `hooks/guard-serena-scope.py` | в тексте ошибки чужие имена каталогов | поправить строку, если мешает |
| `output-styles/serena-first.md` | таблица «какой корень активировать» | переписать под свои проекты |
| `skills/checkpoint/SKILL.md` | примеры с чужим именем машины и проекта | поправить примеры |
| `skills/frontend-design/SKILL.md` | ссылки на правила чужой экосистемы | переписать или удалить навык |
| `serena/global-memory_maintenance.md` | перечисляет чужие экосистемы | переписать под свои |
| `fragments/trah-identity.md` | `personal: true` — «You are Siesta…» | завести свой кусок |

Куски с `personal: true` на чужую машину не ставятся, биографии машины в
репозитории нет вовсе. Но свой кусок про себя и про эту машину завести стоит:
без него сессия не знает, с кем говорит, какая тут оболочка и чем тут собирают.

**Расширение VS Code — отдельно.** Оно запускает CLI само и слова `trah` не
передаёт. Прямой путь к сборке в `claudeCode.claudeProcessWrapper` даст сборку,
но мимо обёртки: ни режима гарда чтения, ни потолка батча, ни брифа. Поэтому
переходник:

```bash
cp trah-setup/bin/claude-trah ~/.local/bin/claude-trah
chmod 0755 ~/.local/bin/claude-trah
```

и `claudeCode.claudeProcessWrapper` — на него.

## Другие ОС

**Windows.** Обёртки-bash нет, поэтому бриф едет не флагом, а через
`~/.claude/CLAUDE.md` — установщик делает это сам, когда видит Windows. Режим
`claude trah` и правки бинарника там не проверялись.

**macOS.** Не проверялся. `stat -c`, `md5sum`, `sha256sum` в обёртке и сборщике
даны в GNU-форме; на macOS это `stat -f`, `md5`, `shasum -a 256`. Отказ
безопасный — обёртка просто запустит `claude` без флага, — но режим потеряется
молча.

## Чего в комплекте нет

- **Плагинов.** `code-review` и `claude-hud` ставятся штатным механизмом
  плагинов Claude Code, не отсюда.
- **Личного.** Биография машины и человека собирается вычисляемыми кусками в
  `~/.claude/fragments/computed/`; в репозитории её нет. Кусок с пометкой
  `computed`, для которого нет тела, просто не попадает в бриф — ни ошибки, ни
  дыры в тексте.

## Как удалить

```bash
python3 trah-setup/bin/install-kit.py --dry-run --home /tmp/проверка   # посмотреть состав
rm -rf ~/.claude/hooks ~/.claude/statusline ~/.claude/brief.md ~/.claude/trah-kit-path
rm -rf ~/.local/share/claude/trah                                      # патченые копии

# точка входа обратно на штатный симлинк
ln -sf ~/.local/share/claude/versions/<новейшая> ~/.local/bin/claude
```

Был свой файл на точке входа — он лежит рядом как `~/.local/bin/claude.before-trah`.

Проводку хуков из `~/.claude/settings.json` уберите руками: установщик писал
туда ключи `hooks`, `permissions.deny`, `env`, `statusLine` и `promptCacheTtl`,
а рядом оставил копию `settings.json.bak-<время>` — из неё же и восстанавливать.

Оригинальные бинарники в `~/.local/share/claude/versions/` комплект не трогает
никогда — удалять там нечего.
