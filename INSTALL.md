# Установка

По шагам, с объяснением каждого. Если ставить будет агент — отдайте ему
[SETUP-AGENT.md](SETUP-AGENT.md), там та же последовательность в виде промпта.

Как оно устроено внутри — [MECHANICS.md](MECHANICS.md).

## Главное свойство этой установки

Поставленный наполовину комплект **не падает**. Он молча ведёт себя не так, как
задумано: хук, которого нет, не кричит — событие просто не срабатывает; кусок,
который не доехал, не жалуется — модель работает обычной.

Поэтому шаг «проверить» в конце не формальность. Это единственный способ
отличить «поставлено» от «похоже на поставленное».

## Слои: что можно не ставить

Три слоя независимы, и любой можно пропустить.

| слой | что даёт | без чего не работает |
|---|---|---|
| хуки, агенты, навыки | гарды, разбор правок, чекпоинт, мерки | python3 |
| бриф | дисциплина инструментов в кешируемой части промпта | обёртка `bin/claude` |
| правки бинарника | то, что снаружи не настраивается ничем | node, npm, git, форк патчера |

Первый слой ставится за минуту и ничего не патчит. Третий — самое ценное и
самое рискованное. Начните с первого, если сомневаетесь.

## Что должно быть на машине заранее

| | зачем | обязательно |
|---|---|---|
| Linux + bash | обёртка — bash-скрипт | да (см. «Другие ОС») |
| `python3` (3.10+) | все хуки и установщик | **да** |
| Claude Code, установленный штатно | оригинал в `~/.local/share/claude/versions/` | **да** |
| `uv` | им ставится Serena | для Serena |
| `node`, `npm` | патчер и MCP-серверы | для правок бинарника |
| `git` | клонировать патчер | для правок бинарника |
| `sha256sum`, `md5sum`, `stat -c` | сверки и кеш обёртки | GNU-форма, есть в Linux |

Проверить разом:

```bash
for t in python3 bash node npm git uv sha256sum md5sum claude; do
  command -v "$t" >/dev/null && echo "есть  $t" || echo "НЕТ   $t"
done
```

## Шаг 1. Забрать комплект

```bash
git clone <адрес этого репозитория> ~/claude-trah
cd ~/claude-trah
```

Дальше все команды — из этого каталога.

## Шаг 2. Serena

Половина комплекта построена вокруг символьного слоя: без Serena хуки
дисциплины будут напоминать о инструментах, которых нет.

```bash
uv tool install --from git+https://github.com/oraios/serena serena-agent
```

Проверить: `serena --help` отвечает.

## Шаг 3. MCP-серверы

Четыре штуки. Ставятся в пользовательскую область, одинаково для всех проектов:

```bash
claude mcp add serena -s user -- ~/.local/bin/serena start-mcp-server --context claude-code

claude mcp add sequential-thinking -s user -- npx -y @modelcontextprotocol/server-sequential-thinking

claude mcp add context7 -s user -- npx -y @upstash/context7-mcp --api-key ВАШ_КЛЮЧ

claude mcp add playwright -s user -- npx -y @playwright/mcp@latest \
  --headless --browser chromium --caps vision --output-dir ~/.claude/playwright-out
```

Про `context7`: ключ заводится на их сайте и **в репозиторий не кладётся
никогда**. Без ключа сервер просто не нужен — пропустите его, остальное
работает.

Про `playwright`: он тянет хромиум, ~656 МБ в `~/.cache/ms-playwright`. Без
этого сервера установщик не поставит навык `browser` — и правильно сделает.

## Шаг 4. Разложить комплект

Сперва вхолостую — посмотреть, что будет сделано:

```bash
python3 trah-setup/bin/install-kit.py --dry-run
```

Потом по-настоящему:

```bash
python3 trah-setup/bin/install-kit.py
```

Что он кладёт: бриф в `~/.claude/brief.md`, трёх агентов, пять навыков,
стиль вывода, все хуки в `~/.claude/hooks/` (режим 0755), кран в
`~/.claude/statusline/`, контекст и память Serena в `~/.serena/`.

Что он **не** трогает: чужие ключи в `settings.json` (заменяется только `hooks`,
`permissions.deny` дописывается без дублей, `env` — через `setdefault`).
Отличающийся файл сохраняется рядом как `<имя>.bak-<время>`.

Если у вас уже своя проводка хуков, установщик её **не заменит** и покажет,
чем она отличается. Согласны потерять свою — повторите с `--replace-hooks`.

В отчёте вы увидите три пропуска — все ожидаемые: навык `browser` без MCP
`playwright`; хуки службы, которых здесь нет; и «куски брифа: нет
`workspace-setup/fragments`». Последнее относится к брифу **службы**, а не
режима: бриф режима лежит собранным в `trah-setup/trah-brief.md` и уезжает в
`~/.claude/brief.md` вместе с остальными 47 файлами.

### Одна ловушка на этом шаге

В проводке есть хук `SessionEnd`, зовущий утилиту `serena-hooks`. Фильтр
отсутствующих утилит её **не отсекает** — имя в фильтре и имя в команде
разошлись. На машине без `serena-hooks` этот хук впишется в настройки и будет
молча падать на каждом закрытии сессии. Вреда нет, но если хотите чисто —
уберите блок `SessionEnd` из `~/.claude/settings.json` руками.

## Шаг 5. Обёртка — единственный шаг руками

Установщик обёртку не ставит намеренно: она подменяет точку входа `claude`, и
такое решение принимает человек.

```bash
cp ~/.local/bin/claude ~/.local/bin/claude.orig-backup 2>/dev/null || true
cp trah-setup/bin/claude ~/.local/bin/claude
chmod 0755 ~/.local/bin/claude
```

Штатный установщик Claude Code кладёт по этому пути **симлинк** на новейшую
версию и пересоздаёт его при каждом обновлении, стирая обёртку. Поэтому в
комплекте есть хук `restore-claude-wrapper.py` на `SessionStart` — он вернёт её
на место. Но путь к образцу у него по умолчанию ведёт в чужой репозиторий,
поэтому скажите ему, где лежит ваш:

```bash
echo 'export GWS_CLAUDE_WRAPPER_KIT="$HOME/claude-trah/trah-setup/bin/claude"' \
  >> ~/.profile
```

Проверить, что обёртка не сломала обычный запуск:

```bash
claude --version     # должна ответить как раньше
```

## Шаг 6. Настройки, которые установщик не ставит

Часть из них — вкусовые, часть выверена замером. Все живут в
`~/.claude/settings.json`.

| ключ | значение | почему |
|---|---|---|
| `effortLevel` | `"medium"` | **выверено**: развёртка по двум задачам показала, что `xhigh` стоит +42 % времени и не даёт ничего |
| `promptCacheTtl` | `"1h"` | час жизни кеша; час записи дороже, но переспрос дешевле |
| `autoCompactEnabled` | `false` | сжатие по заказу, а не по потолку окна |
| `enableWorkflows` | `false` | вместе с запретом `Workflow` в `permissions.deny` |
| `language` | `"Russian"` | комплект русскоязычный |

`env`, `statusLine`, `permissions.deny` и `promptCacheTtl` уже вписаны
установщиком из `settings-hooks.json`.

**Про строку состояния.** `statusLine` указывает на кран `cache-tap.py`, а тот
зовёт дальше `claude-hud.sh` рядом с собой. Этого файла в комплекте нет — он из
плагина `claude-hud`. Не поставили плагин — кран просто молча выйдет, строка
состояния будет пустой, а счёт кеша всё равно будет копиться. Ничего не
сломается.

**Про подагентов.** `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` (агент не зовёт
агента) и `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=6` вписываются установщиком.

## Шаг 7. Правки бинарника

Это главный слой и самый рискованный. Пропустить его можно — всё остальное
работает.

Сперва патчер. Форк, не апстрим: апстримный ломается на модульном бандле
Claude Code с версии 2.1.243.

```bash
git clone https://github.com/skrabe/tweakcc-fixed ~/.local/share/tweakcc-fixed
cd ~/.local/share/tweakcc-fixed
npx --yes pnpm@10 install --ignore-scripts
npx --yes pnpm@10 run build:dev
cd -
```

Теперь сверка — **ничего не пишет**, только называет промахи:

```bash
python3 trah-setup/bin/trah.py check
```

Прицел лежит в `trah-setup/version.txt` (сейчас `2.1.263`). Если у вас другая
версия Claude Code, часть якорей разойдётся — это **штатно**, а не поломка
комплекта: якоря дословные куски минифицированного кода и живут ровно одну
версию. Тогда:

```bash
python3 trah-setup/bin/trah.py upgrade <ваша версия>
```

Команда пройдёт сверку → сборку → проверку доставки → все наборы проверок и
только последним перепишет прицел. Разошедшиеся якоря придётся поправить
руками в `trah-setup/fragments/*.md`; `check` называет их все разом.

Если якоря сошлись — просто собрать:

```bash
python3 trah-setup/bin/trah.py build
python3 trah-setup/bin/trah.py verify    # доехало ли до модели, токенов не стоит
```

Оригинал при этом не трогается: копия ложится в
`~/.local/share/claude/trah/<версия>`, сумма оригинала сверяется до и после.

## Шаг 8. Проверить

Не «должно работать», а фактом.

```bash
# 1. Все наборы проверок комплекта
python3 trah-setup/bin/trah.py tests           # ожидается: наборов 26, сорвалось 0

# 2. Что собрано и что доехало
python3 trah-setup/bin/trah.py status

# 3. Хуки на месте
ls ~/.claude/hooks/ | wc -l

# 4. Гард разрушительных команд жив
python3 ~/.claude/hooks/guard-destructive.test.py    # провалов: 0
```

И живая проба: запустите `claude trah` и спросите сессию, видит ли она в своём
системном промпте строку про символьный слой. Если правки доехали — увидит.

## Шаг 9. Обезличить

В комплекте есть файлы, которые знают чужую машину и чужую экосистему. Они не
ломают работу, но будут давать неверные подсказки.

| файл | что там | что делать |
|---|---|---|
| `hooks/nudge-serena.py` | `_ROOTS_DEFAULT = "~/Ledevia"` — где «наши» деревья | задать `NUDGE_SERENA_ROOTS` своим путём |
| `hooks/restore-claude-wrapper.py` | запасной путь к обёртке | задать `GWS_CLAUDE_WRAPPER_KIT` (шаг 5) |
| `hooks/guard-serena-scope.py` | в тексте ошибки чужое имя корня | поправить строку, если мешает |
| `output-styles/serena-first.md` | таблица «какой корень активировать» | переписать под свои проекты |
| `skills/checkpoint/SKILL.md` | примеры с чужим именем машины | поправить примеры |
| `skills/frontend-design/SKILL.md` | ссылки на правила чужой экосистемы | переписать или удалить навык |
| `serena/global-memory_maintenance.md` | перечисляет чужие экосистемы | переписать под свои |
| `fragments/trah-identity.md` | `personal: true` — «You are Siesta…» | заменить своим текстом |

Куски с `personal: true` на чужую машину установщиком не ставятся. Но если
собираете бриф сами (`trah.py brief`), они поедут — заведите свой.

## Другие ОС

**Windows.** Обёртки-bash нет, поэтому бриф едет не флагом, а через
`~/.claude/CLAUDE.md` — установщик делает это сам, когда видит Windows. Режим
`claude trah` и правки бинарника там не проверялись.

**macOS.** Не проверялся. `stat -c`, `md5sum`, `sha256sum` в обёртке и сборщике
даны в GNU-форме; на macOS это `stat -f`, `md5`, `shasum -a 256`. Отказ
безопасный — обёртка просто запустит `claude` без флага, — но режим потеряется
молча.

## Чего в комплекте нет

- **Брифа службы.** Он собирается Go-сборщиком из соседнего репозитория и в
  сессию не подаётся. Готовый бриф режима лежит в `trah-setup/trah-brief.md` и
  раскладывается установщиком — этого достаточно.
- **Плагинов.** `code-review` и `claude-hud` ставятся штатным механизмом
  плагинов Claude Code, не отсюда.
- **Личного.** Биография машины и человека собирается вычисляемыми кусками в
  `~/.claude/fragments/computed/`, в репозитории её нет.

## Как удалить

```bash
python3 trah-setup/bin/install-kit.py --dry-run --home /tmp/проверка   # посмотреть состав
cp ~/.local/bin/claude.orig-backup ~/.local/bin/claude                 # вернуть точку входа
rm -rf ~/.claude/hooks ~/.claude/statusline ~/.claude/brief.md
rm -rf ~/.local/share/claude/trah                                      # патченые копии
```

Оригинальные бинарники в `~/.local/share/claude/versions/` комплект не трогает
никогда — удалять там нечего.
