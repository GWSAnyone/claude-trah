# Раскладка документации

Читается по поводу: когда заводишь план, пишешь отчёт или ищешь, где продолжить.

## docs/plans/ — журналы задач

Один план — один файл `docs/plans/ГГГГ-ММ-ДД-слаг.md`, дата начала работы.
План — это не список намерений, а запись на диске, по которой работу продолжит
другая сессия после сжатия контекста или перезапуска. Обязательные разделы:

- **«Где я сейчас»** — что сделано, что проверено фактом, какой следующий шаг.
  Правится по ходу работы, а не в конце: сжатие приходит без предупреждения.
- **«Что пробовали и отвергли»** — подход и почему не подошёл, с числом или
  цитатой ошибки. Без этого раздела следующая сессия повторит тупик.
- Решения владельца — дословно и с датой.

Второго файла про ту же задачу не заводить: два файла расходятся.

## docs/reports/ — отчёты проверок

Сюда пишут агент `critical-reviewer` и навык `security`: полный отчёт — файлом,
в сессию возвращается выжимка. Имя — `ГГГГ-ММ-ДД-что-проверяли.md`.

## Указатель на активный план

Хук чекпоинта держит `.claude/.checkpoint-<хост>-<сессия>` — какой план открыт и
с чего продолжать. Руками его не правят.
