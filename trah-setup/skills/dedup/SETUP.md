# Настройка защёлки дублей в проекте

Читается, когда защёлка сказала «в этом проекте не настроена», а владелец
ответил «настроить». Настройка идёт С владельцем: на каждом шаге, помеченном
«спросить», ты предлагаешь и ждёшь ответа, а не решаешь сам. Вопросы задавай
пачкой там, где они не зависят друг от друга, — не по одному за ход.

Что такое защёлка, в двух фразах. Каждую N-ю правку кода хук берёт функции
изменённых файлов и ищет в проекте уже существующие функции с тем же делом.
Найденное судит Haiku, и модели показывается только то, что судья назвал
дублем. Старый долг проекта молчит: при первой проверке строится базовая линия.

Ниже `SETUP` — это `python3 ~/.claude/dedup/dedup-setup.py` (на Windows —
`python %USERPROFILE%\.claude\dedup\dedup-setup.py`).

## 0. Проверить, что инструмент запустится

```bash
SETUP status
```

Строка `uv: НЕТ` — сказать владельцу: защёлке нужен `uv`
(https://docs.astral.sh/uv/), он сам ставит tree-sitter и scikit-learn в свой
кэш при первом запуске; первый запуск качает их из PyPI, без сети не заведётся.
Предложить поставить `uv` или выключить защёлку: `SETUP off`.

## 1. Корень и раскладка — спросить

Корень — каталог, где ляжет `.claude/dedup.json`. Сессии из подкаталогов
находят его поиском вверх. Предложить корень репозитория git (так его и
выбирает `SETUP` по умолчанию).

Раскладка:
- `single` — корень один проект (обычный репозиторий);
- `subprojects` — каждый каталог первого уровня отдельный проект (монорепо
  ботов, каталог с несколькими крейтами-соседями). Тогда дубли МЕЖДУ проектами
  ищутся отчётом `dedup.sh A B --cross`, а защёлка сверяет правку с её проектом
  и общим кодом.

## 2. Что сканировать — спросить

```bash
SETUP survey
```

Вывод — файлы и строки по сторонам (`back` Go, `front` JS, `css`, `html`,
`rust`), каталоги-кандидаты в пропуск и каталоги первого уровня. Показать
владельцу, спросить, какие стороны включить и что пропустить. Правило выбора
пропусков: пропускается код, который держит свою копию НАРОЧНО (стенд, который
не должен тянуть измеряемый модуль; пример как отдельная программа; чужой
вендорный код), иначе защёлка будет звать сводить то, что сводить нельзя.

Пропуски по умолчанию уже включены: `target dist build vendor node_modules
examples benches docs data logs tmp bin testdata backup(s)`, файлы `*_test.go
*.min.js *.min.css tests.rs *_tests.rs build.rs`. Пропуск — по ИМЕНИ каталога
на любой глубине: `data` пропускает и пакет `api/data` в исходниках — если
так у проекта, сказать владельцу.

## 3. Общий код — спросить

Есть ли в проекте общая библиотека, против которой надо ловить «написал заново
то, что там уже есть»? Если есть — внести её в `refs` как
`проект:сторона:путь-от-корня`: правка тогда сверяется и с ней, а сама
библиотека источником находок не бывает.

## 4. Вставка в бриф судьи — спросить

Судья знает общие правила (что такое DUP, IDIOM, NO). Он не знает, что это за
код и какое сходство в нём нарочное. Спросить владельца и записать в
`.claude/dedup-brief.md` по-английски два раздела:

```markdown
## The code you are judging

<две-три фразы: что за система, на чём написана, что в ней важно>

## Traps specific to this project

- <сходство, которое здесь нарочное, и почему>
```

Примеры ловушек из живых проектов: в движке, повторяющем ванильный Minecraft,
порядок вызовов ГСЧ — поведение, а порты разных ванильных классов — IDIOM; в
торговых ботах две площадки с одинаковой формой API — не дубль, если
различаются комиссии или единицы цены. Нечего сказать — файл не нужен.

## 5. Принятые пары — спросить

Файл принятых пар — «не дубль» или «дубль нарочно» с причиной. По умолчанию
`.claude/dedup-accepted.txt`. Спросить, класть ли его в git (тогда решения
видят все, кто работает с репозиторием) или держать локально.

## 6. Частота

По умолчанию — каждая 5-я правка кода. Замер 30.09.2026: проверка без находок
1,5 с, с судьёй 8–10 с. Владелец скажет другое — поставить его число.

## 7. Записать

```bash
SETUP on --layout single --scopes rust --skip-dirs research,netbench \
    --refs '' --every 5
```

Команда пишет `.claude/dedup.json` со `state: "on"` и проверяет, что ядро
запускается. Базовая линия построится сама на первой проверке.

## 8. Показать, как оно видит проект — по желанию

```bash
~/.claude/dedup/dedup.sh .:rust --judge 20 --only-dup
```

Двадцать сильнейших групп с меткой судьи. Показать владельцу три-четыре
примера: так он поймёт, что будет приходить в сессию. Сводить найденное —
отдельная работа по скиллу `dedup`, не часть настройки.

## Выключить и вернуть

```bash
SETUP off                 # в этом проекте, пока не включат
SETUP setup               # снова «не настроено»: хук опять предложит настройку
DEDUP_LATCH=0 claude …    # на одну сессию
```

## Windows — что проверить руками

Код писался и проверялся на Linux. Сделано переносимым, но на живой Windows
НЕ проверялось:

- **Замки** — через `msvcrt.locking` вместо `fcntl`. Если две сессии на одном
  проекте теряют находки или хук висит — смотреть сюда (`dedupconf.lock`).
- **Бинарь судьи** ищется в `%USERPROFILE%\.local\share\claude\versions\`
  (имя версии с `.exe` или без) и `...\claude\trah\current`. Если у установки
  Claude Code другой путь — задать `DEDUP_JUDGE_BIN` в окружении на полный путь
  к `claude.exe` (НЕ к обёртке: судья должен идти голым бинарём).
- **`dedup.sh`** — bash; хук и `SETUP` его не используют, зовут
  `uv run … dedup.py` напрямую. Человеку в PowerShell — та же команда руками.
- **`uvx treepeat`** (сигнал shape в полном отчёте) — нужен `uvx` в PATH.
  Нет его — отчёт без сигнала shape; защёлка shape не использует.
- **Пути в id пар** пишутся с `/` на любой системе: файл принятых пар можно
  делить между Linux и Windows. Старые принятые пары с `\` не сработают.
- **Проводка хука** в `settings.json` ставится установщиком с полным путём к
  python; если хук молчит вовсе — проверить, что этот путь существует.
